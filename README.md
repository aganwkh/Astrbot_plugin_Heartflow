# 心流插件 (Heartflow)

基于双LLM架构设计的简单心流模式智能群聊主动回复系统

## 🌟 功能特色

- **智能判断**：使用小参数模型快速判断是否需要回复群聊消息
- **高质量回复**：使用AstrBot配置的大型LLM生成自然流畅的回复
- **群聊隔离**：每个群聊独立的状态管理和精力系统
- **频率控制**：智能控制回复频率，避免过度活跃
- **Token 防护**：单消息与总上下文双重预算，并限制 Zalgo 组合符、控制字符和异常重复字符
- **并发安全**：判断使用不可变历史快照，同一群同时最多一个判断请求
- **人格缓存**：按人格内容版本缓存摘要，并持久化到 AstrBot 插件数据目录
- **配置灵活**：支持多种参数调节，适应不同群聊环境

## 🏗️ 架构设计

```
判断小模型 (用户配置) → 快速决策 → 大型回复模型 (AstrBot现有配置) → 高质量回复
```

## 🏗️ 推荐使用模型

Gemma 27b，可在Google Aistudio获取密钥后使用，每天免费14400次，基本满足需求

### 判断维度
1. **内容相关度** (0-10)：消息是否有价值、有趣、适合回复
2. **回复意愿** (0-10)：基于当前精力状态的回复意愿
3. **社交适宜性** (0-10)：回复是否符合群聊氛围
4. **时机恰当性** (0-10)：考虑频率控制和时间间隔
5. **对话连贯性** (0-10)：是否自然承接机器人上次发言

## ⚙️ 配置说明

### 必要配置
1. **启用插件**：`enable_heartflow = true`
2. **小参数判断模型配置**：`judge_provider_name`：在AstrBot中配置的提供商名称

### 可选配置
- `reply_threshold`：回复阈值 (0-1，默认0.6)
- `energy_decay_rate`：精力衰减速度 (默认0.1)
- `energy_recovery_rate`：每5分钟精力恢复量 (默认0.02)
- `context_messages_count`：最多使用的历史消息条数 (默认10)
- `max_message_chars`：单条消息字符上限 (默认1200，保留首尾)
- `max_context_chars`：历史与当前消息的动态上下文总预算 (默认6000，最新优先)
- `judge_include_reasoning`：是否要求判断模型返回理由 (默认false)
- `judge_max_retries`：JSON解析失败后的最大重试次数 (默认1)
- `min_reply_interval_seconds`：两次 Heartflow 主动回复的最短间隔 (默认0)

所有数值配置都会在运行时校验并安全钳制。五项权重会归一化；如果全部无效或为0，则回退到默认权重。

### 白名单配置
- `whitelist_enabled`：启用群聊白名单 (默认false)
- `chat_whitelist`：群聊白名单列表 (默认[])

#### 白名单使用说明
当启用白名单模式时，只有在白名单中的群聊才会触发心流回复：



获取群聊ID的方法：

## 🚀 使用指南

### 1. 安装配置
1. 将插件放置在 `packages/heartflow/` 目录
2. 重启AstrBot加载插件
3. 在插件配置中设置判断模型提供商名称
4. 启用插件：`enable_heartflow = true`
5. 可选：配置群聊白名单限制插件作用范围


### 2. 管理命令
- `/heartflow`：查看当前群聊的心流状态和最近一次判定
- `/heartflow_reset`：重置当前群聊的心流状态

### 群聊接话判断

心流会根据最近的群聊消息判断当前发言承接的句子和说话对象，也会参考 QQ 的 @ 和引用。明确接机器人先前发言的追问可以继续对话。明确说给其他群友的话留给对方，对象不明确时等后续消息。

现有参与者之间约活动、组队或分工时，心流会保持安静。消息里另有面向全群的提问或招募时，心流只判断开放的部分。

开放话题要有具体的接话点并达到回复阈值才会主动冒泡。主模型按当前人格措辞，可以放弃不自然的插话。主动回复会先完整生成，超过 60 秒或触发消息已被引用回复时取消。最近的判定可在群里用 `/heartflow` 查看，被跳过的判断也可以在插件的 DEBUG 日志中查看。

## 📊 状态说明

### 精力系统
- **精力值范围**：0.1 - 1.0
- **消耗机制**：只有 Heartflow 触发的主模型结果进入发送后 hook，才扣减精力并计入主动回复
- **恢复机制**：使用独立的 `last_energy_update_time` 按时间恢复；读取状态不会改写 `last_reply_time`
- **每日恢复**：跨日首次读取状态时额外恢复0.2精力

## 🔧 高级配置

### 权重调整
插件内置权重配置：
```python
weights = {
    "relevance": 0.25,
    "willingness": 0.20,
    "social": 0.20,
    "timing": 0.15,
    "continuity": 0.20,
}
```

### 群聊个性化
可以通过修改代码实现不同群聊的个性化配置：
- 技术群：提高相关度权重
- 闲聊群：提高社交适宜性权重
- 工作群：提高时机恰当性权重

## 📈 监控建议

1. **观察回复质量**：调整回复阈值
2. **监控回复频率**：调整精力参数和时间间隔
3. **分析判断日志**：优化判断提示词
4. **收集用户反馈**：持续改进回复策略

DEBUG 级别会输出一行不含原文的 `[HeartflowJudge]` 指标，包括历史条数/字符数、当前消息字符数、人格摘要字符数、完整 prompt 字符数、截断数和清洗数。判断历史只在 prompt 中出现一次，Provider 的 `contexts` 固定为空。

## 🔍 故障排除

### 常见问题
1. **不回复任何消息**
   - 检查判断模型提供商配置是否正确
   - 确认插件已启用
   - 检查是否启用了白名单但当前群聊不在白名单中
   - 查看日志中的错误信息

2. **回复过于频繁**
   - 提高回复阈值
   - 增加精力衰减速度
   - 增加最短回复间隔

3. **回复质量不佳**
   - 检查AstrBot的LLM配置
   - 优化判断提示词
   - 调整权重配置

4. **特定群聊不回复**
   - 检查白名单配置是否正确
   - 确认群聊ID是否在白名单中
   - 查看debug日志确认过滤原因

### 日志信息
- `🔥 心流触发主动回复`：判断通过并将事件标记为主动唤醒
- `更新主动状态`：主模型结果进入发送后 hook，主动统计完成提交
- `[HeartflowJudge]`：不含聊天原文的 Token/截断观测指标

## 🔌 插件交互说明

- Heartflow 群消息监听优先级为 `1000`。若同时使用 GroupDebouncer（常见优先级 `2000`），Heartflow 接收其最终放行的合并事件。
- 被 @、命令或其他插件唤醒的群消息仍会写入历史，但不会再次调用 Heartflow 判断模型。
- 判断模型通过 Provider 直接调用，不进入 AstrBot 主回复 hook，因此不会触发 LivingMemory 的主回复注入链。
- 所有 Bot 群聊文本都会进入历史；只有带 Heartflow 一次性标记的模型结果会计入主动回复统计。
